# Архитектура памяти и контекста

Как Claude помнит то, что ему важно помнить, и забывает то, что не важно.

## Главная идея

Claude не имеет встроенной долгой памяти. Каждая сессия начинается с нуля. Чтобы он не задавал одни и те же вопросы и не повторял одни и те же ошибки, мы складываем «память» в обычные markdown-файлы внутри git-репозитория.

- Сессия закрылась → Claude забыл.
- Файлы остались → следующая сессия их прочитает.
- Файлы под git → история, ревью, откат, синхронизация между машинами.

## Слои контекста, от общего к частному

```
┌─────────────────────────────────────────────────────────┐
│ Слой 1. ~/.claude/CLAUDE.md                             │
│ Глобальные личные правила (язык, тон, общие принципы)   │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│ Слой 2. <репо>/CLAUDE.md                                │
│ Карта проекта: папки, кодовые слова, продукты           │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│ Слой 3. <репо>/rules/*.md                               │
│ Правила-расширения: стиль, кодинг, точность, безопасн.  │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│ Слой 4. <подпроект>/context.md                          │
│ Архитектура подпроекта (lazy-загрузка)                  │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│ Слой 5. <подпроект>/current-focus.md                    │
│ Рабочий блокнот: TODO, тупики, открытые вопросы         │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│ Слой 6. MEMORY.md + memory/*.md                         │
│ Долгая память между сессиями (факты, не правила)        │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│ Слой 7. Skills (~/.claude/skills/)                      │
│ Триггерные навыки (поведение по фразам пользователя)    │
└─────────────────────────────────────────────────────────┘
```

## Что Claude читает в начале сессии

**Авто-загружается каждую сессию:**
- `~/.claude/CLAUDE.md` (Слой 1)
- `<репо>/CLAUDE.md` (Слой 2, если cwd внутри git-репо)
- `MEMORY.md` (Слой 6 — короткий индекс, до 200 строк)

**Lazy-загружается по необходимости:**
- `rules/*.md` (Слой 3) — когда упомянуто соответствующее правило или сработал триггер
- `<подпроект>/context.md`, `decisions.md` (Слой 4) — когда задача касается подпроекта
- `current-focus.md` (Слой 5) — когда продолжаем работу с предыдущей сессии
- `memory/<type>_<name>.md` (Слой 6) — когда тема пересекается с записью

## Подробно по слоям

### Слой 1. `~/.claude/CLAUDE.md`

Глобальные личные правила. Применяются ко всем проектам на машине. Сюда — то, что не зависит от конкретного репо: язык ответов, тон, личные предпочтения.

Шаблон: `templates/global-CLAUDE.md`.

### Слой 2. `<репо>/CLAUDE.md`

Карта проекта: какие папки за что отвечают, какие маркеры в запросе ведут к какому файлу. Главная точка входа в проектный контекст.

Шаблон: `templates/project-CLAUDE.md`.

### Слой 3. `rules/*.md`

Доменные правила: безопасность, точность данных, стиль кода, управление сессиями. Один файл = один домен, ~50-100 строк.

Базовый набор поставляется с пэком. Свои правила добавляются по мере роста проекта (через `rules/correction-to-rule.md` workflow).

### Слой 4. `<подпроект>/context.md`

Архитектурное описание подпроекта: стек, ключевые сущности, поток данных, инварианты. Читается lazy.

Шаблон: `templates/context.md`.

### Слой 5. `<подпроект>/current-focus.md`

Рабочий блокнот текущей сессии. Что в работе, тупики, открытые вопросы. Обновляется **на ходу**, не в конце.

Шаблон: `templates/current-focus.md`.

### Слой 6. `MEMORY.md` + `memory/*.md`

Долгая память между сессиями. `MEMORY.md` — короткий index (всегда в контексте). Отдельные `<type>_<name>.md` — содержание, lazy.

Типы: user / feedback / project / reference. Подробно — в `memory/README.md`.

### Слой 7. Skills

Триггерные навыки в `~/.claude/skills/<name>/SKILL.md`. Активируются по фразам пользователя или явному вызову `/skill-name`.

Skills хранят повторяющиеся workflow'ы, не сами правила. Пэк ставит семь универсальных: `close` (зафиксировать контекст перед закрытием терминала), `handoff` (промт для продолжения в новой сессии), `write` (редактура текстов), `diplomat` (резкое → рабочее), `council` (четыре параллельных агента для стратегического решения), `memory-audit` (чистка долгой памяти), `refine` (решение через две другие модели: Optimizer/Auditor → Judge, два раунда). Скиллы лежат в `~/.claude/skills/` и линкуются в `~/.agents/skills/` — эту папку читают и Codex, и Kimi, и Qwen. Свои доменные скиллы (`/deploy`, `/audit` и т.п.) добавляешь сам.

### Среда Claude Code (`~/.claude/`)

Помимо слоёв контекста пэк настраивает саму среду на машине, чтобы новый комп не приходилось донастраивать руками:

- `~/.claude/settings.json` — права (allow/deny), нижняя панель (statusLine), хуки (предупреждение перед push, syntax-check после правок, дрифт-метки, канарейка), ultrathink на каждый промпт по умолчанию, полноэкранный TUI.
- `~/.claude/statusline.js` — рисует панель: модель, папка, ctx-токены и %, лимиты 5ч/7д с таймером сброса, цена сессии (`statusline-command.sh` — запасной bash-вариант).
- `~/.claude/hooks/*` — скрипты хуков. Два «датчика качества»: `drift-markers.py` собирает метки `#длинно/#вода/#круги` из промтов в `~/.claude/drift-markers.tsv` (недельный зачёт дрейфа), `canary-name-check.py` подсвечивает ответ, который не начался с имени пользователя (`~/.claude/canary-name`) — ранний признак потери контекста.
- Другие CLI: `codex-home/` (`~/.codex/AGENTS.md`, hooks), `qwen-home/` (`~/.qwen/QWEN.md`), `kimi-home/` (сниппет усилия). Один и тот же набор правил живёт в нейтральных `rules/`, а каждый агент получает свой adapter и не читает чужие.
- `~/.claude/.mcp.json` — MCP-серверы: `playwright` (готов сразу) + `google-sheets`/`google-docs` (указывают на серверы внутри репо, нужны venv + credentials). Генерируется из `claude-home/.mcp.json.template` подстановкой пути репо.
- Shell-алиас `<имя-репо>` в `~/.zshrc`/`~/.bashrc` → `cd <repo> && claude`.

Источники в пэке: `claude-home/` и `skills/`. Установщик не затирает существующие настройки — если `settings.json` или `.mcp.json` уже есть, показывает образец и предлагает слить вручную. Credential-bound MCP (sqlite с путём к БД и т.п.) в пэк не входят — добавляются через `claude mcp add` на конкретной машине.

## Переход между сессиями (handoff)

Когда сессия близка к завершению (явный триггер от пользователя или потеря контекста):

1. Обновить `current-focus.md` — что сделано в этой сессии, что осталось, тупики.
2. Если приняты важные решения — занести в `decisions.md`.
3. Сгенерировать промт для следующей сессии и положить в буфер (`pbcopy` / `xclip`).

Подробно — в `rules/session-management.md` § «Завершение сессии».

## Что куда писать (шпаргалка)

| Тип знания | Куда |
|------------|------|
| «Всегда отвечай на языке вопроса» | `~/.claude/CLAUDE.md` |
| «Не показывай код в ответах» | `~/.claude/CLAUDE.md` |
| «Перед правкой формулы — прочитай живые данные» | `rules/data-accuracy.md` или новый `rules/*.md` |
| «Юзер — продуктовый менеджер, 10 лет опыта» | `memory/user_*.md` |
| «Юзер не любит длинные сводки в конце ответа» | `memory/feedback_*.md` |
| «Релиз 1.0 запланирован на 2026-06-01» | `memory/project_*.md` |
| «Логи лежат в Datadog, проект "api-prod"» | `memory/reference_*.md` |
| «В проекте 5 продуктов: X, Y, Z, W, V» | `CLAUDE.md` проекта |
| «Архитектура auth-сервиса» | `auth/context.md` |
| «Сегодня доделать рефакторинг X» | `current-focus.md` |
| «Миграция БД на Postgres, 12 шагов, 3 сессии» | `<project>/plans/YYYY-MM-DD-<slug>.md` + строка в корневом `## Status` |

## Что НЕ хранить в файлах

- API-ключи, токены, пароли (никогда, ни в одном `.md`)
- Содержимое `.env`-файлов
- Подробности фиксов багов (они в `git log` и в самом коде)
- Файловая структура проекта (она в `ls`)
- Дубли того, что уже есть в `git log` / `git blame`

## Правило одной записи

Один факт = одно место. Если правило записано в `rules/coding.md`, оно не должно дублироваться в `CLAUDE.md`. Если факт в `memory/`, не дублировать в `rules/`.

Дубли расходятся при изменениях, и Claude видит конфликт. Конфликт = непредсказуемое поведение.

## Принципы пэка

- **Минимум магии.** Всё в обычных markdown-файлах в git. Откатывается, ревьюится, диффится.
- **Память в файлах, не в Claude.** Ничего не зависит от внутреннего состояния модели.
- **Правила побеждают исправления.** Если Claude ошибся одинаково дважды — это не его проблема, это отсутствующее правило.
- **Ничего лишнего на старте.** Claude читает только `CLAUDE.md` и `MEMORY.md`. Остальное подгружает, когда задача того требует.
