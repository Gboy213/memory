# Claude Code — система правил и контекста

Готовый набор правил, шаблонов и архитектуры памяти для работы с Claude Code. Ставится за 1 минуту, дальше развивается под себя.

Полезен, если:
- Ты используешь Claude Code в рабочем проекте и хочешь, чтобы он не забывал контекст от сессии к сессии.
- Тебя бесит когда модель повторяет одни и те же ошибки или задаёт одни и те же вопросы.
- Хочешь системно подходить к управлению контекстом, а не каждый раз изобретать заново.

## Установка

### Способ 1 — через Claude Code (рекомендуется)

В рабочем git-репозитории открой Claude Code и скажи:

> Установи систему правил из `github.com/Gboy213/memory` — там `INSTALL.md` с инструкцией.

Claude прочитает [`INSTALL.md`](INSTALL.md), склонирует пэк во временную папку, разложит файлы по местам (не затирая твои наработки, если они уже есть), отчитается. Через минуту всё стоит.

### Способ 2 — bash one-liner

```bash
cd /path/to/your/repo
curl -fsSL https://raw.githubusercontent.com/Gboy213/memory/main/install.sh | bash
```

То же самое, но через скрипт. Защита от перезаписи такая же — твои существующие файлы не пострадают.

### Что после установки

1. Открой `CLAUDE.md` в корне репо — это карта твоего проекта. Заполни папки, ключевые слова, правила.
2. Открой `~/.claude/CLAUDE.md` — глобальные личные правила. Подправь под себя: язык, тон, предпочтения.
3. По мере работы — обновляй `current-focus.md`, складывай заметки в `memory/`.

Подробная философия слоёв — в [`ARCHITECTURE.md`](ARCHITECTURE.md).

Существующие файлы не затираются.

## Идея в двух абзацах

Claude не помнит вчерашний разговор. Каждая новая сессия начинается с нуля. Память хранится в файлах внутри репозитория. Сессия закрылась → Claude забыл. Файлы остались → следующая сессия их прочитает.

Слои контекста идут от общего к частному: глобальные правила в `~/.claude/CLAUDE.md`, правила проекта в `CLAUDE.md` репо, правила-расширения в `rules/`, архитектура подпроекта в `context.md`, рабочий блокнот в `current-focus.md`, долгая память между сессиями в `MEMORY.md` и `memory/*.md`. Подробно — в [`ARCHITECTURE.md`](ARCHITECTURE.md).

## Принципы пэка

- **Минимум магии.** Всё лежит в обычных markdown-файлах в git. Откатывается, ревьюится, диффится.
- **Память в файлах, не в Claude.** Ничего не зависит от внутреннего состояния модели.
- **Правила побеждают исправления.** Если Claude ошибся одинаково дважды — это не его проблема, это отсутствующее правило. Записал → не повторится.
- **Ничего лишнего на старте.** Claude читает только `CLAUDE.md` и `MEMORY.md`. Остальное подгружает, когда задача того требует.
- **Защита от перезаписи.** Установка не затирает твои существующие файлы — если файл уже есть, его не трогают.

## Обновление

Когда я обновляю пэк (добавляются правила, шаблоны улучшаются) — у тебя в проекте останется старая версия. Чтобы подтянуть свежее:

> Обнови систему правил из `github.com/Gboy213/memory` — см. `INSTALL.md`.

Claude покажет diff каждого изменённого файла, спросит что взять. Никаких автоматических перезаписей.
