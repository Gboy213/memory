## Правила работы

### Общие

- **Стиль общения** — сухо, в суть. `rules/communication.md`.
- **Кодинг** — минимум кода, хирургические правки, думать перед кодом. `rules/coding.md`.
- **Точность данных** — цифры только с проверяемым следом. `rules/data-accuracy.md`.
- **Search First** — проверь готовое в репо до написания нового. `rules/search-first.md`.
- **Безопасность** — не читать `.env`, удаление с подтверждением. `rules/security.md`.
- **Целостность контекста** — верифицировать правки, не доверять exit code 0. `rules/context-integrity.md`.
- **Сессии** — `current-focus.md` обновлять на ходу, handoff при триггерах. `rules/session-management.md`.

### Триггеры скиллов

- **Тексты** (причеши/перепиши/лендинг) → скилл `write`.
- **Дизайн UI** (предложи дизайн X) → `rules/design-proposals.md`, 5 пунктов до кода.
- **Зеркалирование прода** (повтори как в проде) → `rules/mirror-prod.md`.

### Самоконтроль

- Любая коррекция от пользователя → исправить + предложить правило → записать в нужный слой. `rules/correction-to-rule.md`.
- 3+ одинаковых tool-вызова → СТОП, поменять подход. `rules/loop-detection.md`.

### Крупные работы

- **План крупной работы как файл** — `<project>/plans/YYYY-MM-DD-<slug>.md`. Создаётся ДО начала, если работа на 2+ сессий / 3+ шагов / затрагивает deploy. Не для bugfix'ов и косметики. `rules/plans.md`.

## Git

- Работаем в ветке `main`
- На старте сессии: `git pull --ff-only`
- Перед массовым рефакторингом — сначала `git commit` текущего состояния
- После изменений: `git add` → `git commit` → `git push`
