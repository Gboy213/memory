# Словарь точностных триггеров

Готовые команды пользователя → точный режим Claude. Один и тот же смысл для обоих. Цель — повысить точность через **источник и след**, а не через «думай/проверь дважды».

## Главный принцип

Точность дают не «думать больше» и не «проверить дважды», а две вещи:
1. **Назвать источник истины** и сверить с ним (а не взять из памяти/канона/гипотезы).
2. **Потребовать след** — откуда каждый факт; где знаю точно, где предполагаю.

## Словарь команд

| Команда пользователя | Что Claude обязан сделать |
|---|---|
| **«покажи след»** / «откуда каждое число» | Для каждой цифры/факта — ссылка на источник (файл/ячейка/строка кода/лог). Нет источника → не писать число (Zero Fabrication, `data-accuracy.md`). |
| **«где знаешь, где предполагаешь»** | Явно разделить: проверенный факт vs гипотеза/интерполяция. Слабые места наружу. |
| **«сверь с первоисточником»** | Открыть первичный документ/реестр/код/таблицу/лог ПЕРЕД утверждением. Не верить памяти, канон-документу, handoff, своей прошлой пометке. |
| **«триангулируй»** | Подтвердить факт **тремя независимыми** источниками разной природы (не один трижды). Сошлись до копейки → твёрдо. Разошлись → нашёл баг, стоп. |
| **«при расхождении стоп»** | Если источники не сходятся — не выбирать молча, не строить нарратив. Остановиться, показать расхождение, спросить. |
| **«это боевое»** / «прод» | Highest bar (`verify-before-act.md § Необратимое касание`): путь из резолвера, read-only режим явно, гипотезу об инфре проверить объективно (бэкап-снапшот/git/stat) ПЕРЕД действием. |
| **«ничего не меняй пока не покажешь что проверил»** | Сначала вывести план проверки + результаты, действие — только после ОК. |

## Триангуляция — что это (термин)

Из навигации: определить точку по **трём** независимым ориентирам — где их направления пересекаются. Один ориентир — ты на линии (не знаешь где). Два — две возможные точки. Три — одна, сомнений нет.

С фактами: один источник может врать, два совпасть случайно, **три независимых разной природы — нет**. Пример: первичный документ + системная выгрузка из сервиса + независимый учётный реестр дали одну сумму до копейки → факт твёрдый; на стыке источников поймалась запись, которая туда не относилась (выглядела похоже, но была другой природы).

**Критично — независимость.** Перечитать один файл 3 раза ≠ триангуляция (один ориентир трижды, та же ошибка трижды). Сверить с 3 разными источниками = триангуляция.

## Что НЕ повышает точность фактов

- **«ultrathink» / «подумай глубже»** = думать больше. Полезно для **дизайна, рассуждения, неоднозначных решений**. НО для фактов: если рассуждаю по памяти в неверную сторону — больше думания = более **уверенная** ошибка. Думание ≠ проверка.
- **«двойная/тройная проверка»** без указания ЧЕМ проверить — расплывчато, рискует стать ритуалом (посмотреть один источник N раз). Лучше: «триангулируй» или «сверь с <источник>».
- **«будь точен» / «не ошибись»** — не задаёт механизм. Заменить на «покажи след» / «где предполагаешь».

## Самая сильная одна фраза

**«покажи источник каждого факта и где ты не уверен».** Почти невозможно выполнить, фабрикуя — приходится открывать первоисточник. Активирует и след, и разделение знаю/предполагаю.

## Где ставки → какой уровень

1. **Обычная задача** — базовые правила, спец-команды не нужны.
2. **Важное число/расчёт/факт** — «покажи след; где знаешь, где предполагаешь».
3. **Деньги / необратимое / прод** — «триангулируй из независимых; при расхождении стоп; это боевое».
