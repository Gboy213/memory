# Mirror Prod — зеркалируй прод, не изобретай

## Когда применять

Задачи на зеркалирование прод-кода: концепт-прототипы, мокапы, редизайн существующей зоны, копирайт, «сделай как в проде, но с правкой X».

**Триггеры в запросе:**
- «сверстай как на проде», «повтори [зону]», «отзеркаль», «1 в 1»
- «прототип [существующего экрана]», «концепт [компонента]»
- «поправь копи у [блока]», «отредактируй текст [страницы]»
- «редизайн [модуля]» — структура мигрирует, но контент/лейблы берутся из прода

## Правило

Перед ЛЮБОЙ правкой задачи на зеркалирование — СНАЧАЛА прочитать прод-источник и зафиксировать дословные значения.

1. Открыть prod-файл (HTML/CSS/JS/текст) — НЕ по памяти, через Read
2. Выписать дословно: лейблы, dropdown-значения, заголовки, структуру сетки, имена CSS-токенов, классы
3. Только после этого править прототип — копируя зафиксированные значения, без парафраза
4. Если значений много — перед правкой вывести список в сообщении пользователю («нашёл в проде X, Y, Z — буду использовать их»)

## Что запрещено

- Изобретать strategy-имена, dropdown-опции, лейблы, заголовки, копирайт
- Заменять prod-значения «похожими по смыслу» («Переговоры» вместо «Блогеры»)
- Строить кастомный лейаут «как мне кажется должно быть» вместо копирования prod-структуры (кастомный 5-колоночный grid вместо prod blogger-card)
- Додумывать факты про продукт (характеристики, материалы, фичи, свойства)

## Проверка перед commit

- Каждый лейбл/значение/класс в прототипе можно показать строкой из prod-файла
- Структура (grid columns, flex, DOM-дерево) соответствует prod
- Если что-то в прототипе отсутствует в проде — это осознанное добавление, согласованное с пользователем

## Источники правды

| Область | Source of truth |
|---------|-----------------|
| Веб-приложение | `<app>/static/` (HTML, CSS, JS), его README/help |
| Дизайн-система | `<design-repo>/` (брифы и спеки). Дизайн-токены — SoT в production-коде, копий в дизайн-репо нет |
| Сайт | `<site>/` |
| Копирайт продуктов | `product/*.md` |
| Тексты ботов | `<bot>/prompts/` |
| Отчёты/уведомления (формат сообщений) | `<reports>/app/*.py` |

## Параллельная агентная проверка

Для крупных прототипов — спаунить параллельного Agent (Explore) с задачей: «прочитай prod, верни: (1) dropdown-значения с цитатами, (2) все лейблы, (3) grid/flex структуру, (4) CSS-токены». Затем мирроить по отчёту, а не по памяти.
