# Loop Detection — обнаружение зацикливания

## Правило

При выполнении задач отслеживай повторяющиеся действия:

- **3+ одинаковых tool вызова** (тот же инструмент с похожими аргументами) → СТОП, предупреди пользователя: «Похоже, я зацикливаюсь. Попробовал X три раза, результат тот же. Варианты: [альтернативный подход]»
- **5+ попыток** → полный СТОП. Не пробовать дальше. Диагностика: что пошло не так, почему не работает, что попробовать иначе
- **Одна и та же ошибка 2 раза** → не повторять третий раз. Проанализировать причину, попробовать другой подход

## Типичные ловушки

| Паттерн | Что происходит | Что делать |
|---------|---------------|-----------|
| Edit → ошибка → тот же Edit | Ищу не ту строку или файл изменился | Перечитать файл, найти точное совпадение |
| Bash → exit code 1 → тот же Bash | Команда не работает, повторяю надеясь на другой результат | Прочитать ошибку, поменять подход |
| Search → не найдено → тот же Search | Ключевое слово не то | Поменять запрос, расширить/сузить |
| Save → conflict → Save | Конфликт не разрешён | Сначала разрешить конфликт, потом save |

## Не путать с iteration

Нормально: 5 разных Edit в одном файле (каждый — другая правка).
Зацикливание: 5 одинаковых Edit (одна и та же строка, один и тот же текст).

Ключ: **результат меняется?** Да → iteration. Нет → loop.
