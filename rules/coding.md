# Правила кодинга

Антидот к типичным ошибкам LLM при написании и правке кода. Применяется ко всем код-задачам в репо.

## 1. Минимум кода (Simplicity First)

**Минимум кода, который решает задачу. Ничего сверх.**

- НЕ добавлять фичи, которые не просили
- НЕ создавать абстракции для одноразового кода
- НЕ добавлять «гибкость» / «конфигурируемость», которую не запрашивали
- НЕ писать error handling для невозможных сценариев
- Если получилось 200 строк, а можно 50 — переписать

**Тест:** «Senior engineer сказал бы что это переусложнено?» Если да — упростить.

**Антипаттерны:**
- Класс с одним методом, который вызывается один раз
- `try/except` вокруг кода, который не может упасть
- Параметры функции «на будущее», которые сейчас никто не передаёт
- Конфиг-файл / env-переменная для значения, которое меняется раз в год
- Validation на внутренних функциях, куда невалидные данные не доходят

## 2. Хирургические правки (Surgical Changes)

**Трогать только то, что нужно. Убирать только свой мусор.**

При правке существующего кода:
- НЕ «улучшать» соседний код, комментарии, форматирование
- НЕ рефакторить то, что не сломано
- Соблюдать существующий стиль, даже если ты бы сделал иначе
- Если заметил несвязанный мёртвый код — упомянуть, НЕ удалять

**После правки убирать осиротевшее:**
- Импорты, переменные, функции, которые **твои** изменения сделали неиспользуемыми — удалить
- Pre-existing мёртвый код — НЕ удалять без явной просьбы

**Тест:** Каждая изменённая строка должна напрямую трассироваться к запросу пользователя.

**Антипаттерны:**
- Правишь функцию X — заодно переименовываешь переменные в функции Y «для консистентности»
- Меняешь логику — заодно перетасовываешь импорты «по алфавиту»
- Фиксишь баг — заодно добавляешь docstring, type hints, комментарии «для ясности»
- Заменяешь `'` на `"` (или наоборот) в файлах, которые трогаешь

## 3. Перед кодом — думать

**Не предполагать молча. Не скрывать сомнения. Показывать развилки.**

Перед написанием:
- Сформулировать допущения явно. Если неуверен — спросить
- Если возможны несколько интерпретаций задачи — показать их, НЕ выбирать молча
- Если есть вариант проще — сказать. Возражать аргументированно
- Если что-то непонятно — стоп. Назвать, что именно непонятно. Спросить
