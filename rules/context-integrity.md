# Целостность контекста и верификация

## Проблема

Claude Code читает файлы с лимитом (2000 строк / ~25K токенов). При auto-compaction (~167K токенов) ранние сообщения сжимаются — содержимое файлов, цепочки рассуждений, промежуточные решения теряются. После 15+ сообщений агент может галлюцинировать имена переменных и ломать то, что только что понимал.

## Чтение файлов

- **Файл >500 строк** — читай чанками: offset=0 limit=500, потом offset=500 limit=500 и т.д.
- **Не доверяй одному Read** на большой файл — проверяй что прочитал всё нужное
- **Перед правкой** — перечитай файл, если прошло >3 сообщений с момента последнего чтения или файл >200 строк. Не правь по памяти из ранних сообщений
- **После правки** — проверь синтаксис (ast/node --check). Перечитывать весь файл — только если правка сложная или файл большой

## Верификация изменений

### Код
- **Python:** `python3 -c "import ast; ast.parse(open('file.py').read())"`
- **JavaScript/JSON:** `node --check file.js` / `python3 -c "import json; json.load(open('file.json'))"`
- **Bash:** `bash -n script.sh`
- **Если есть тесты** — прогони их после правки

### Конфиги и данные
- **JSON/YAML** — проверь валидность парсером
- **Google Sheets формулы** — после записи прочитай ячейку обратно
- **HTML** — открой в браузере или проверь структуру

### Деплой
- **После git push** — проверь что push прошёл (exit code + output)
- **После systemctl restart** — проверь `systemctl status` (active/running)
- **После rsync** — проверь что файлы долетели
- **Деплой на VPS** — ВСЕГДА: `git commit` → `git push` → deploy. Не наоборот. На VPS есть cron (repo-pull.sh), который перезапишет ручной деплой из git. После программной правки HTML — проверить структуру (`grep -c 'ключевые_id' файл`)

### UI / CSS после переноса макета в прод
- **«HTML и CSS 1-в-1 с макетом ≠ рендер 1-в-1».** Разный каскад, родители, reset, версия движка — дают разный computed size на одинаковом CSS.
- **После переноса компонента** — сразу попросить пользователя прислать DevTools-скрины computed size контрольных элементов (строка таблицы, высота футера, заголовок) и сравнить с макетом. Не отчитываться «готово» по факту деплоя.
- **Известные ловушки:**
  - `box-sizing: border-box` **не работает надёжно на `<th>` / `<td>`** (W3C-спека). Не комбинировать `padding: V H` + `height: Y` на table cells — padding добавится сверху. Паттерн: `padding: 0 H; height: Y` + `vertical-align: middle; line-height: 1`.
  - `zoom: X` применяется разными алгоритмами к flex-items и к inline-width элементам — накапливает subpixel-разъезд на длинных сетках (см. [22] в bugs.md).
  - Глобальный `* { box-sizing: border-box }` может быть перебит user-agent stylesheet'ом для спец-элементов (table cells).
- **Контроль высоты строки/блока:** формула `total_height = height + vertical_padding + vertical_border`, если box-sizing не гарантирован. Если нужна ровно `Y px` — вертикальный padding `0`, остальное через `line-height` / `vertical-align`.

## Длинные сессии (10+ правок)

- На 10-м и 20-м сообщении — перечитай рабочие файлы (ранний контекст мог сжаться)
- Если путаешь имена или номера строк — стоп, перечитай
- Если чувствуешь что теряешь контекст — предложи /compact

## Принцип

Не доверяй exit code 0. Не доверяй "успешно записано". Не доверяй своей памяти о файле из 10 сообщений назад. Открой и проверь.
