# Безопасность и защита данных

## Защита чувствительных данных

**НИКОГДА не читай и не выводи в чат содержимое:**
- Файлов `.env`, `credentials.json`, `*.key`, `*.pem`, токенов, паролей
- Любых файлов, которые могут содержать API-ключи, секреты, пароли
- Если нужно работать с таким файлом — спроси пользователя, какие именно значения подставить, но НЕ читай файл сам

**Если пользователь просит создать `.env` или подобный файл:**
- Создай шаблон с плейсхолдерами (`API_KEY=ВСТАВЬ_СЮДА`)
- Пользователь сам впишет реальные значения

## Защита от удаления

**Перед ЛЮБЫМ удалением файлов или папок — ВСЕГДА спрашивай подтверждение.**

- Показать ЧТО именно будет удалено (полные пути)
- Показать СКОЛЬКО файлов затронуто
- Дождаться явного «да» / «удаляй» от пользователя
- Команды `rm`, `rm -r`, `rm -rf` — ТОЛЬКО после подтверждения
- НИКОГДА не удалять домашнюю директорию, корневые папки, `~/.claude/`, `~/.ssh/`, `~/.config/`

## Опасные WebFetch URL

Некоторые сайты ломают сессию Claude Code из-за JS-рендеринга, антибота или огромного объёма. Список ведётся в `<repo>/CLAUDE.md` проекта; для них использовать Playwright MCP (`browser_navigate` + `browser_snapshot`) или попросить пользователя скопировать текст вручную.

## Push в публичный repo

Перед `git push` в публичный repo — обязательная проверка содержимого diff'а на:
- API-ключи / токены / секреты (паттерны `sk-`, `ghp_`, `AIza`, длинные base64/hex)
- Email, IP-адреса, ID внешних сервисов (Google Sheets ID, Telegram chat IDs)
- Имена юрлиц, клиентов, сотрудников, домашние пути

Если репо был приватным, а становится публичным — проверка двойная (`grep` + параллельный agent с независимым аудитом).
