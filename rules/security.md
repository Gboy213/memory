# Безопасность и защита данных

## Защита чувствительных данных

**НИКОГДА не читай и не выводи в чат содержимое:**
- Файлов `.env`, `credentials.json`, `*.key`, `*.pem`, токенов, паролей
- Любых файлов, которые могут содержать API-ключи, секреты, пароли
- Если нужно работать с таким файлом — спроси пользователя, какие именно значения подставить, но НЕ читай файл сам

**Если пользователь просит создать `.env` или подобный файл:**
- Создай шаблон с плейсхолдерами (например: `API_KEY=ВСТАВЬ_СЮДА`)
- Пользователь сам впишет реальные значения

## Защита от удаления

**Перед ЛЮБЫМ удалением файлов или папок — ВСЕГДА спрашивай подтверждение.**
- Показать ЧТО именно будет удалено (полные пути)
- Показать СКОЛЬКО файлов затронуто
- Дождаться явного "да" / "удаляй" от пользователя
- Команды `rm`, `rm -r`, `rm -rf` — ТОЛЬКО после подтверждения
- НИКОГДА не удалять домашнюю директорию, корневые папки, ~/.claude/, ~/.ssh/, ~/.config/

## WebFetch и сайты с антиботом

Некоторые сайты (тяжёлый JS-рендеринг + антибот-защита) вешают WebFetch — сессия зависает. Признак: документация, которая в браузере открывается, а через WebFetch не отдаёт текст.

**Что делать:**
1. Сначала ищи локальную копию/README по этому API в репо.
2. **Playwright MCP** (рекомендуется): `browser_navigate` → `browser_snapshot` — проходит антибот, рендерит JS. Snapshot большой страницы может быть огромным — используй точечную навигацию по разделам.
3. Или попроси пользователя скопировать текст.

Заведи свой список «проблемных» доменов по мере того, как находишь их — чтобы не натыкаться повторно.
