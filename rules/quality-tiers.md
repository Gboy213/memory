# Бизнес-классы системы — вектор внимания аудитов и оценок качества

Аудиты залипают на мелочах в экспериментальных модулях наравне с ядром.
Качество меряется НЕ равномерно по репо, а по бизнес-весу модуля.

## 4 класса

| Класс | Что это | Политика качества и аудита |
|-------|---------|---------------------------|
| **CORE** | Зарабатывает и считает деньги | Полный стандарт: тесты, идемпотентность, reliable-mutations, аудит с P1 |
| **SUPPORT** | Держит CORE (инфра) | Аудит да; severity — по влиянию на CORE |
| **EXPERIMENT** | Пробы новых способностей | Аудит НЕ ходит. Строится дёшево, без полировки — осознанно. Вопрос один: «этим пользуются?» Нет → DORMANT или снос |
| **DORMANT** | Закрытое/архив | Не аудировать, не чинить, находки = мусор |

## Реестр модулей

<!-- Заполни под свой репо: одной строкой на класс, путями. Пример: -->

**CORE:** <модули, которые считают деньги или обслуживают клиента: `src/billing`,
`src/orders`, боевая БД и каналы данных в неё>.

**SUPPORT:** <бэкапы и восстановление, деплой-скрипты и systemd, smoke/мониторинг,
тесты, hooks, дизайн-система и её сторожа, безопасность (auth, secrets)>.

**EXPERIMENT:** <живые пробы с датой начала: `src/labs/...`>.

**DORMANT:** <закрытые проекты и архивы: `archive/...`>.

## Правила (обязательны для ВСЕХ аудитов: Claude, Codex, Kimi, Qwen)

1. **Severity-cap:** находка может быть P1/P2 только в CORE/SUPPORT. Каждая
   находка аудита ОБЯЗАНА нести тег класса модуля. Находки по EXPERIMENT —
   отдельная секция «вне бизнес-скоупа» (заметки, без приоритета), по
   DORMANT — не включать вовсе.
2. **EXPERIMENT не полируют.** Единственный аудит-вопрос к эксперименту —
   «пользуются ли». Не пользуются → предлагается перевод в DORMANT или снос,
   НЕ фиксы. Фикс в EXPERIMENT — только по явному решению владельца.
3. **Новый модуль рождается с классом.** Новая фича/скрипт — сразу указать
   класс здесь (одной строкой). EXPERIMENT осознанно строится дёшево.
4. **Переклассификация — решение владельца,** фиксируется здесь с датой.
5. **Спорный/неупомянутый модуль** — аудитор помечает «класс не определён»
   и спрашивает, а не решает сам.
