# Управление контекстом и сессиями

## current-focus.md

- Обновлять **на ходу** — после завершения логического блока (закрыл подзадачу, принял архитектурное решение, нашёл блокер), не в конце сессии. Мелкие правки (1-2 строки, опечатка) — не повод
- Разросся >~300 строк — СТОП, свернуть: закрытые/неактуальные сессии целиком в `<project>/changelog.md` (новые сверху), в фокусе только живое. Перенос **как есть, не сжимать** (changelog = архив), сверить построчно до и после.

## Синхронизация документации после структурных изменений

- Любое структурное изменение (новый столбец, формат, формула, переименование, новый файл/скрипт) → обновить ВСЕ md-файлы, описывающие область (current-focus.md, context.md, CLAUDE.md и др.) **В ТОМ ЖЕ действии**
- **Задача НЕ завершена, пока документация не обновлена.** Забыл — это баг, чинить немедленно

## Каскад adapter-файлов (sync с другими ИИ)

Правка `CLAUDE.md` (корень или `*/CLAUDE.md`), меняющая кодовые слова / карту проектов / RBAC / scope правил / объявленный канон (налог/маржа/выручка/% МП) — **в том же коммите** проверить и обновить `agents.md` (Codex) и `GEMINI.md`. Без sync — каскадные галлюцинации в аудит-сессиях сторонних ИИ (прецеденты round 8/9).

## Самодиагностика и ленивая загрузка

- Теряю контекст (забыл что делал, путаю файлы, повторяю вопросы) — **СТОП**: обновить md проекта, выдать промт для новой сессии, предложить перезапуск
- НЕ читать тяжёлые файлы на старте сессии (длинные `context.md`, `decisions.md`, `bug-registry.md`) — только когда реально нужны; что читать на старте — в `CLAUDE.md` проекта

## Короткие сессии

Большую задачу — порциями по 3-5 подзадач; после порции обновить md, оценить остаток контекста. Лучше 3 коротких продуктивных сессии, чем 1 длинная с потерей контекста.

## Протокол /compact

- Делать проактивно после логического куска (закрыл подзадачу, принял 2-3 решения), не ждать конца контекста; Claude **сам предлагает** момент
- Перед: обновить `current-focus.md`, сообщить «логический кусок завершён, рекомендую /compact»
- Сохранять при сжатии: цели сессии, принятые решения, открытые вопросы/блокеры, план шага. Удалять: примеры, промежуточные варианты, болтовню, содержимое прочитанных файлов
- После: перечитать `CLAUDE.md` + `current-focus.md` проекта, подтвердить «контекст восстановлен, продолжаем с [задача]»

## Пороги контекста

У Claude НЕТ инструмента измерения заполненности — проценты НЕ называть (выдуманные числа). Сигналы на практике: путаю имена/строки, перечитываю те же файлы внутри одного блока. За индикатором в UI следит пользователь.

## Завершение сессии

Любой триггер = **НЕМЕДЛЕННЫЙ СТОП** всей работы. Никаких «ещё один шаг», никаких «может доделаем?».

**Триггеры:**
- Явные фразы: «останови/заканчивай/стоп сессию», «сделай промт», «новая сессия / идём в новую», «заверши», «сворачивайся», «хватит на сегодня» и любые комбинации
- Автоматические: индикатор контекста «почти полный», /compact не помогает

**Протокол (обязателен при любом триггере):**
1. Обновить md проекта: `current-focus.md` (статус, что сделано, что осталось + секция **«Тупики»** — подходы, которые НЕ сработали), `decisions.md` (незафиксированные решения), рабочие файлы
2. Готовый промт для следующей сессии: контекст (проект, сессия), что сделано, что НЕ доделано (конкретные задачи), точные инструкции продолжения
3. Промт в code block **и** в буфер через `pbcopy`

При явных фразах — немедленно, при автоматических триггерах — автоматически.
