# Управление контекстом и сессиями

## Обновление current-focus.md

- Обновляй `current-focus.md` **на ходу** — после завершения логического блока, а не в конце сессии
- Логический блок = закрыл подзадачу, принял архитектурное решение, нашёл блокер. Мелкие правки (1-2 строки, фикс опечатки) — не повод обновлять

### Свёртка при разрастании
- `current-focus.md` распух (> ~300 строк) — СТОП, свернуть: закрытые/неактуальные сессии целиком перенести в `<project>/changelog.md` (новые сверху), в фокусе оставить только живое (активные задачи, блокеры, открытые вопросы)
- Перенос — **как есть, не сжимать** (changelog = архив); сверить построчно до и после, ни одной строки не потерять

## Синхронизация документации после структурных изменений

- После ЛЮБЫХ структурных изменений (новый столбец, изменённый формат, новая формула, переименование, новый файл, новый скрипт) — обновить ВСЕ md-файлы, которые описывают изменённую область
- Не только `current-focus.md`, но и `context.md`, `CLAUDE.md` и любые другие
- Делать это **В ТОМ ЖЕ действии** — не откладывать «на потом»
- **Задача НЕ считается завершённой**, пока документация не обновлена
- Если забыл обновить .md — это баг, который нужно исправить немедленно

## Каскад adapter-файлов (sync с другими ИИ)

При любой правке `CLAUDE.md` (корень) или `*/CLAUDE.md`, которая меняет таблицы «Кодовые слова», карту проектов, RBAC, scope правил, или объявленный канон (налог/маржа/выручка/% МП) — **в том же коммите** проверить и при необходимости обновить:

- `agents.md` — адаптер для Codex (короткий контекст, своя секция Sheets-через-Python)
- `GEMINI.md` — адаптер для Gemini

Без sync — каскадные галлюцинации в аудит-сессиях сторонних ИИ (round 8 нашёл 3 drift'а Money Panel `admin-only` vs `admin+partner`; round 9 — `Admin-only` в agents.md:79 снова).

## Самодиагностика

- Если чувствуешь, что теряешь контекст (забыл что делал, путаешь файлы, повторяешь вопросы) — **СТОП**
- Обнови все md-файлы проекта, выдай пользователю промт для новой сессии и предложи перезапуск

## Ленивая загрузка

- НЕ читай тяжёлые файлы на старте сессии (длинные `context.md`, `decisions.md`, `bug-registry.md`)
- Читай их ТОЛЬКО когда они реально нужны для текущей задачи
- Какие файлы читать на старте — указано в `CLAUDE.md` каждого проекта

## Короткие сессии

- Большую задачу разбивай на порции по 3-5 подзадач
- После выполнения порции — обнови md, оцени оставшийся контекст
- Лучше 3 коротких продуктивных сессии, чем 1 длинная с потерей контекста

## Протокол /compact

Когда делать:
- После завершения логического куска (закрыл подзадачу, принял 2-3 решения)
- НЕ ждать пока контекст закончится — делать проактивно
- Claude должен **сам предложить** /compact пользователю, когда видит подходящий момент

Перед /compact (делает Claude):
1. Обновить `current-focus.md` проекта (что сделано, что осталось)
2. Сообщить пользователю: "Логический кусок завершён, рекомендую /compact"

Что сохранять при сжатии (инструкция для автосжатия):
- Цели текущей сессии
- Принятые решения
- Открытые вопросы и блокеры
- План следующего шага
- Удалять: примеры, промежуточные варианты, болтовню, содержимое прочитанных файлов

После /compact (делает Claude):
1. Перечитать `CLAUDE.md` проекта для восстановления рамок
2. Перечитать `current-focus.md` для восстановления состояния
3. Кратко подтвердить пользователю: "Контекст восстановлен, продолжаем с [задача]"

## Пороги контекста

У Claude НЕТ инструмента для измерения заполненности контекста. НЕ называть проценты — это выдуманные числа.

Вместо этого:
- **После завершения логического блока** — предложить /compact (без привязки к цифрам)
- **Если начинаешь путать имена/строки** — СТОП, предложить /compact
- **Пользователь** следит за индикатором в UI и делает /compact когда нужно

## Завершение сессии

### Триггеры завершения (любой из них = НЕМЕДЛЕННЫЙ СТОП)

**Явные фразы пользователя:**
- «останови сессию», «заканчивай сессию», «стоп сессия»
- «сделай промт», «сделай новый промт», «промт для новой сессии»
- «новая сессия», «идём в новую сессию», «переходим в новую сессию»
- «заверши», «сворачивайся», «хватит на сегодня»
- Любая комбинация вышеперечисленного

**Автоматические триггеры:**
- Индикатор контекста в UI подсветился как «почти полный» (точного процента у Claude нет — см. § «Пороги контекста»). На практике: если внутри одного логического блока приходится перечитывать те же файлы заново или путать строки — сигнал
- Сообщение о /compact не помогает

### Протокол завершения (ОБЯЗАТЕЛЕН при ЛЮБОМ триггере)

**СТОП = прекратить ВСЮ текущую работу. Никаких "ещё один шаг". Никаких вопросов "может доделаем?". Сразу к протоколу:**

1. **Обновить md файлы проекта:**
   - `current-focus.md` — актуальный статус, что сделано в этой сессии, что осталось
   - `current-focus.md` секция **«Тупики»** — подходы, которые НЕ сработали (чтобы следующая сессия не повторяла ошибки)
   - `decisions.md` — если были приняты решения, не зафиксированные ранее
   - Все рабочие файлы (CLAUDE.md и т.д.) — сохранить незавершённые изменения
2. **Написать готовый промт для следующей сессии:**
   - Контекст: какой проект, какая сессия
   - Что сделано в текущей сессии
   - Что НЕ доделано (конкретные задачи)
   - Точные инструкции для продолжения
3. **Выдать промт пользователю в code block И скопировать в буфер обмена** через `pbcopy`

**Это должно происходить АВТОМАТИЧЕСКИ** при автоматических триггерах и **НЕМЕДЛЕННО** при явных фразах.
