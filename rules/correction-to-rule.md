# Correction → Rule

## Триггер (автоматический)

Любая коррекция от пользователя = триггер. Без исключений:
- Явное "не так, сделай X"
- Спокойное "поменяй X на Y"
- Повтор инструкции, которую уже давал (= Claude нарушил)
- Claude сам заметил что сделал не то

## Протокол (обязательный, без пропусков)

1. **Исправить** то, что просит пользователь
2. **СТОП.** Нельзя продолжать работу пока не выполнены шаги 3-5
3. **Анализ первопричины.** Не "что пошло не так", а "какое отсутствующее правило это допустило"
4. **Предложить правило** — конкретная формулировка, которая системно предотвращает повторение
5. **Маршрутизация** — куда записать (см. ниже)
6. **Записать** после одобрения пользователя
7. **Только потом** продолжать работу

## Маршрутизация правил (куда записывать)

Приоритет: ближе к месту использования = лучше.

| Куда | Когда | Пример |
|------|-------|--------|
| **SKILL.md** | Правило специфично для скилла | "/audit должен проверять X" |
| **rules/*.md** | Доменное правило (безопасность, данные, интеграции) | "Перед правкой формулы — прочитать живые данные" |
| **CLAUDE.md проекта** | Правило уровня проекта | "Кириллица/латиница в MATCH формулах" |
| **~/.claude/CLAUDE.md** | Кросс-доменное, редко | "Не показывай код в ответах" |

## Куда НЕ записывать правила

**memory/** — ЗАПРЕТ на правила, процедуры, алгоритмы. Memory = только факты (контекст, решения, справочные данные). Правило поведения Claude в memory = ошибка.

Исключение: `memory/feedback_*.md` с type=feedback — допустимо для мягких предпочтений ("пользователь предпочитает X"). Жёсткие правила ("всегда делай X") — в rules/skills/CLAUDE.md.

## Почему это критично

Без записанного правила любое "исправление" — косметика. Ошибка повторится в другом контексте, в другой сессии, после compaction. Claude не "запоминает" уроки без записанных правил.
