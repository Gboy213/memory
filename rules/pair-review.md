# Парное ревью (pair-review) — протокол двух моделей

Цикл «одна модель делает → другая критикует по первоисточникам → первая закрывает
находки» объективно даёт результат лучше соло на крупных и необратимых работах.

## Роли

- **Делатель** — модель, чья сессия ведёт работу. Делает целиком, коммитит
  атомарно, пушит. Не параллельно с другой моделью в тех же файлах
  (staged-захваты чужих файлов — известный класс инцидентов).
- **Критик** — другая модель. Ревьюит ПО ПЕРВОИСТОЧНИКАМ (код, git log, сервер,
  прод), не по описанию делателя. Находки — сначала списком, не чинить молча.
- **Арбитр** — владелец. При споре PASS/FAIL и после 2 раундов.

## Порог (когда pair-review обязателен)

Только CORE-мутации (`rules/quality-tiers.md`): миграции БД, DR/инфра, соседство
с защищённой бизнес-логикой, кампании >10 файлов. Мелочь идёт соло (под порог
попадает ~10–20% работ).

## Шина

`<папка аудитов>/handshake/` — файлы-эстафеты, коммитятся в main (durable-история).
Имя: `YYYY-MM-DD-<slug>.review-needed.md` → после критика `*.review-done.md`.

Контракт файла (frontmatter):

```
---
author: codex | claude | kimi
target: codex | claude | kimi
status: review-needed | review-done | fixed
round: 1 | 2
---
```

Тело: что сделано → как проверено (источники) → что НЕ сделано → вопросы критику.
Критик дописывает секцию «Вердикт критика»: PASS/FAIL по пунктам + цитата
первоисточника + предложение фикса; меняет status на review-done.

## Стоп-правила

- Максимум 2 раунда (`round` в frontmatter). Третий раунд — владелец.
- Не ревью-ревью-ревью. Критик не ревьюит собственный фикс.
- Коммит сразу после add (staged-захват параллельной сессией — реальные инциденты).
- Маркер в commit message делателя: `[pair-review]`.

## Автоматика (по желанию)

Вотчер по расписанию: git pull → находит `*.review-needed.md` → запускает критика
headless (`claude -p` / `codex exec`) с промтом-ревьюером → критик дописывает
файл, переименовывает в review-done, коммитит. Кап ретраев: после 3 неудачных
прогонов файл переименовывается в `*.review-failed.md` с ALERT в лог — дальше
разбирает человек. Вотчер регистрируется в карте инфраструктуры репо.

Обратная сторона: сессия делателя при старте либо по запросу читает
`*.review-done.md` и закрывает находки коммитом `status: fixed`.

## Анти-паттерны

- Парный аудит всего подряд (дорого, медленно — порог выше).
- Критик без первоисточника (взаимные галлюцинации вместо контроля).
- Две модели одновременно в одном файле.
