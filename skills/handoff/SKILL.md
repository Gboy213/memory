# Session Handoff

When this skill triggers — stop. Drop whatever you were working on. Every token spent on the old task steals from a quality handoff.

The goal: следующая сессия должна продолжить ровно с того места, где эта остановилась, без угадывания и перечитывания всех файлов.

## Когда триггерить

**Явные триггеры от пользователя:** «сделай промт», «новая сессия», «заканчивай», «сворачивайся», «хватит на сегодня», «handoff», «промт для продолжения»

**Автоматические триггеры (предлагать пользователю):**
- Активная работа >2 часов в одной сессии (предложить: «работаем долго, может handoff и в новую сессию?»)
- Большое количество tool-вызовов (>100 за сессию) — контекст близок к /compact
- Сообщение системы про сжатие контекста уже сработало

## Принцип построения handoff

**Указывай на источники истины, а не пересказывай их.** Текст в handoff — lossy формат для понимания. Реальное состояние = живые файлы + git + БД. Handoff должен указать новой сессии где смотреть, а не пытаться воспроизвести содержимое.

Правильно: «`last_commit: 4ecd476`, `files_in_focus: src/feature.py`»
Неправильно: «В сессии я переписал функцию X в файле Y, изменил логику Z, теперь она делает A, B, C, ...»

## Step 1: Понять что изменилось в сессии

```bash
git status -u
git diff --stat HEAD
git log --oneline -5
```

Если working tree clean и нет новых коммитов — отметить явно: сессия была exploratory ИЛИ всё уже закоммичено.

## Step 2: Обновить документацию проекта

ТОЛЬКО то что реально изменилось. Не трогать актуальные файлы.

Файлы (если есть в проекте):
- **current-focus.md** — что сделано, что осталось, блокеры
- **decisions.md** — новые решения, не записанные ранее
- **context.md** — структурные изменения (новые сущности, переименования, схемы)
- **CLAUDE.md** — если изменились команды, пути, ссылки

Если в этой сессии добавляли или удаляли крупные инициативы в `current-focus.md` — отметь это в handoff отдельной строкой, чтобы новая сессия пересмотрела приоритеты.

## Step 3: Собрать handoff в строгом формате

**Формат (НЕ менять, НЕ добавлять секции):**

```
project: [название]
domain: [конкретный домен, не широкая тема]
session: N (продолжение N-1)
last_commit: [SHA + первая строка сообщения]
git_status: clean | dirty (с перечислением файлов если dirty)
files_in_focus:
  - [path/to/file] ([краткое состояние, если незавершён])
  - [path/to/file]
blockers:
  - [блокер, если есть. null если нет]
prev_handoff: [.handoffs/файл если есть, null если первая]

## DONE
- [конкретное действие с путём файла / коммитом]
- [конкретное действие]

## LEFT (ровно 1 пункт)
- [одна следующая задача как ДЕЙСТВИЕ с критерием готовности]

## NEXT (дословная команда для следующей сессии)
Прочитай: [список конкретных файлов через запятую]
Продолжи: [одна команда что делать]
```

**Правила:**
- LEFT = РОВНО 1 пункт. Если их 5 — выбери самый важный, остальные в `current-focus.md`. Длинный LEFT превращает следующую сессию в выбор «с чего начать»
- DONE = факты с указателями (коммит SHA, file:line), не пересказ
- NEXT = команда, не описание. Новая сессия буквально может скопировать и выполнить
- Без em-dash (--) — нарушение `rules/writing.md § HARD BANS`
- Без mini-summary в конце («таким образом, мы...») — нарушение `rules/communication.md`

**Пример хорошего DONE:**
> - `4ecd476` fix(auth): дедуп токенов при рефреше (issue #128 частично, кейс с истёкшим refresh закрыт)
> - `src/views/sales.py:42-89` — расчёт CPO готов, тест прошёл

**Пример плохого DONE:**
> - Работал над модулем, починил несколько багов, переделал views

## Step 4: Сохранить В ДВА МЕСТА

1. **Файл:** `<project>/.handoffs/YYYY-MM-DD-HHMM-<slug>.md` где slug — короткое имя домена (sales-view, auth-refactor)
2. **Буфер обмена:** `pbcopy` всего содержимого

```bash
mkdir -p <project>/.handoffs
echo "<handoff content>" > <project>/.handoffs/YYYY-MM-DD-HHMM-<slug>.md
echo "<handoff content>" | pbcopy
```

Зачем дубль: если буфер потерян (другие copy/paste), handoff остаётся в файле. Если файл удалён случайно — есть буфер.

## Step 5: Сообщить пользователю

Одно короткое сообщение:
> Handoff сохранён в `.handoffs/2026-05-23-2245-sales-view.md` и в буфер. Можно делать /compact или новую сессию.

Без «надеюсь это поможет», без «удачи в следующей сессии».

## Что делать в новой сессии при подхвате handoff'а

(Это для будущего Claude. Описано здесь чтобы handoff skill знал что нужно генерировать.)

Новая сессия на старте:
1. Проверить есть ли свежий handoff в `<project>/.handoffs/` за последние 24ч (см. `rules/session-start.md`)
2. Если есть — прочитать его, прочитать упомянутые в `files_in_focus` файлы, выполнить команду из `NEXT`
3. Если handoff старше 24ч — сказать пользователю «есть старый handoff от DATE, читать?» и ждать ответа
4. Если handoff'а нет — старт как обычно

## Принципы

- **Указатели важнее пересказа** — `last_commit: SHA`, `file:line` вместо «я переписал функцию X»
- **LEFT = 1 пункт** — не 5, не 3. Один. Иначе новая сессия теряется в выборе
- **NEXT = команда** — не план, не описание. Дословный текст что делать
- **Без раздутия** — лучше 15 точных строк, чем 50 размытых
- **Указывай домен узко** — «auth: рефактор refresh-токенов», не «auth»
