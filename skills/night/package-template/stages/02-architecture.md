# Этап 02 — Архитектура и задокументированные решения

Сверь код с решениями: <`*/context.md`, `*/decisions.md`, правила архитектуры репо>.

1. Границы слоёв: UI → API → БД; шаблон / адаптер / данные.
2. Один мастер на сущность; двойная запись только там, где это решение записано.
3. Крупная механика без документации (есть в коде, нет в decisions/context) — задокументируй.
4. Решение записано, но код делает иначе — находка с двумя строками (дока vs код).

Помни правило достаточности: не более одного предложения «изменить архитектуру» за
ночь, и только если оно убирает живой баг или доказанный дубль. Остальное — не находки.
Код архитектурно не меняешь; расхождения в доках чинишь сам.
