# night — одна сквозная бизнес-миссия за ночь

Вечером `/night` (Claude Code) / `$night` (Codex) / `/skill:night` (Kimi). Пока ты
спишь, три модели проверяют один законченный бизнес-поток твоего репозитория от
источника до результата: ведущая идёт по потоку и пишет существенные находки в общий
журнал, проверяющая сверяет их по первоисточникам, судья выносит ACCEPT / MODIFY /
REJECT. Простое ведущая чинит сразу (тесты → коммит → push → деплой по контракту),
спорное ждёт твоего «да» утром. Утром — сводка простыми словами в терминале и, если
настроен хук, в Telegram.

```
ведущая (Primary) ──► находки ──► проверяющая ──► судья ──► приговоры
      ▲                                                        │
      └──────── финальный круг: согласен / спорю с новым следом ◄┘   (кругов максимум два)
```

Ведущая модель ротируется по ночам: codex → claude → kimi. Две другие становятся
проверяющей и судьёй. Qwen ведущим не бывает: в headless у него нет shell.
Принудительно: `PRIMARY=kimi bash ~/.agents/skills/night/run.sh`.

## Движок и пакет

| Где | Что | Кто правит |
|---|---|---|
| `~/.claude/skills/night/` (этот пакет, ссылка `~/.agents/skills/night`) | движок: `run.sh`, `board.py` (журнал), `pick_zones.py` (выбор миссии), `roles/` (промты проверяющего, судьи, финального круга), `stages/zone-audit.md` (сквозной чеклист) | обновляется из пэка, руками не трогать |
| `<repo>/night/` | пакет репо: `contract.md` (правила и права ночи), `zones.tsv` (реестр миссий), `summary.md` (формат сводки), `reports/` (отчёты, в git), `logs/` и `state/` (gitignore) | ты и твой Claude |

Пакет может переопределить любой файл движка (`roles/*.md`, `stages/zone-audit.md`,
`summary.md`) — положи свою версию с тем же именем в `night/`. Спец-чеклист одной
миссии: `night/stages/zone-<id>.md`.

Два необязательных хука в пакете:
- `notify.sh "<текст>"` — как уведомить владельца (старт не удался, ночь остановлена,
  сводка готова). Пример — `package-template/notify.sh.example` (Telegram через curl).
- `preflight.sh` — доступы, без которых ночь мертва (ssh до сервера деплоя, токен
  API). Ненулевой код + причины в stdout → ночь не стартует, причины в `state/HOLD`
  и в уведомлении.

## Установка в свой репо (один раз)

1. `cp -r ~/.agents/skills/night/package-template <repo>/night` (или попроси Claude:
   «создай пакет night из шаблона движка»).
2. Заполни `night/contract.md`: что это за репо, таблица контуров (вход-доки, чем
   тестируется, как деплоится), что модель чинит сама, что ждёт твоего решения.
   Это главный документ — он ограничивает, что модели могут менять ночью.
3. Заполни `night/zones.tsv`: одна строка = один сквозной бизнес-поток (не папка!),
   его границы в коде, входные доки, команда проверки, ожидаемый бизнес-результат.
   Начни с 3–5 миссий; класс `CORE` — то, что зарабатывает или считает деньги,
   `SUPPORT` — то, что держит CORE.
4. По желанию `night/notify.sh` и `night/preflight.sh`.
5. Проверка: `bash ~/.agents/skills/night/run.sh --dry-run` из корня репо печатает
   миссию, ведущую и проверяющие модели. Первый живой прогон — с самой безопасной
   миссией и `--only <id>`, днём, в foreground, чтобы посмотреть, как модели себя ведут.

Условия старта: ветка main, чистое дерево, `codex`/`claude`/`kimi` в PATH и
залогинены (подписки, не API-ключи), ноут не спит (`caffeinate` на macOS раннер
вешает сам).

## Как ставить задачу

Ночь не принимает произвольное задание — она проверяет один поток из реестра.
Поэтому «задача» ставится в двух местах:

- **Реестр `zones.tsv` — заранее.** Хорошая миссия отвечает на вопрос «можно ли доверять
  этому потоку»: `заявка → платёж → договор → статусы без дублей и потерь`. Плохая —
  «проверить папку `app/`». Колонка `runtime` — тот самый бизнес-результат: по нему
  ведущая формулирует тезис и по нему же ты утром понимаешь, что доказано.
- **Вечером в чате — только выбор.** `/night` — автоматический выбор самой давней
  миссии; `/night восстановление` или `/night <id миссии>` — конкретная. Не пиши ночью
  «найди все баги»: модели переключатся в режим сбора мелочи, и утром ты получишь
  список гигиены вместо ответа про поток.
- **Утром — решения.** `/night` показывает выжимку; отвечаешь «да 2», «нет 1».
  Всё, что модели не могут сделать сами, лежит в отчёте с готовым diff.

Что считается результатом: «инварианты доказаны, существенных дефектов нет» — нормальный
итог. Находка обязана иметь severity (Critical / High / Medium), след, воспроизведение и
бизнес-эффект; `Low`, косметика и документационная пыль в сводку не попадают.

## Права ночи (задаются в contract.md)

Разумный дефолт из шаблона: модель сама чинит дрифт доков, CSS к канону, мёртвый код с
доказательством «0 вхождений», мелкие баги ≤30 строк с тестом; коммит на правку, push,
деплой штатными скриптами. Ждёт тебя: архитектура, удаление/перемещение файлов,
деньги и защищённая бизнес-логика, инфра/cron, большие патчи. Откат любой правки —
`git revert <sha>`.

## Запуск / проверка
```bash
bash ~/.agents/skills/night/run.sh --dry-run             # план
bash ~/.agents/skills/night/run.sh                       # ночь (в фоне: nohup … &)
bash ~/.agents/skills/night/run.sh --only <id миссии>    # одна конкретная миссия
NIGHT_PKG=night python3 ~/.agents/skills/night/pick_zones.py --list   # давность миссий
```
Стоп: `kill <pid из night/logs/<дата>/runner.log>`; после `kill -9` — `rmdir /tmp/night-<repo>.lock`.
Капы: миссия 7 ч (`STAGE_TIMEOUT`), ночь 9,5 ч (`MAX_NIGHT_SECONDS`), новая миссия не
стартует после 07:30 (`NIGHT_END`). Заход роли 1500 с (`ROLE_TIMEOUT`).

## Как запускаются модели (headless)
- codex: `codex exec --ephemeral -s danger-full-access --json -c approval_policy=never -` (без sandbox: вложенные claude/kimi пишут в свои домашние папки).
- claude: `claude -p --output-format json --dangerously-skip-permissions --no-session-persistence`.
- kimi: `kimi -p "<промт>" --output-format stream-json`.

Все три получают полный доступ к машине на ночь. Границы задаёт только `contract.md`
и то, что ведущая модель его соблюдает — поэтому первый прогон делай днём и смотри.

## Файлы движка
| Файл | Что |
|---|---|
| `run.sh` | раннер: preflight, одна миссия, параллельные роли, финальный круг, сводка, уведомление. Пакет без `zones.tsv` работает старым этапным режимом (`stages/01..07` пакета) |
| `board.py` | общий журнал ночи: находки → проверка → приговор → ответ ведущей → применённое (append-only JSONL, каждая роль пишет в свой файл) |
| `pick_zones.py` | выбор миссии по давности и свежим правкам, cooldown 7 дней, `--list`, `--done` |
| `roles/auditor.md`, `roles/judge.md`, `roles/hunter-final.md` | промты проверяющей, судьи и финального круга ведущей |
| `stages/zone-audit.md` | сквозной чеклист: тезис → живые сигналы → поток → отказы → результат → гейт существенности |
| `package-template/` | заготовка пакета репо: `contract.md`, `zones.tsv`, `summary.md`, `stages/01..07` (этапный режим), примеры хуков |

Внутри промтов пути движка и пакета подставляются раннером: `{{NIGHT}}` → папка
движка, `{{PKG}}` → папка пакета относительно репо.
